# AMMBEC Denver urban methane — analysis code

Reproducible R pipeline behind the manuscript on airborne methane source
apportionment and emission estimates over the Denver metropolitan area, using the
NOAA **AMMBEC** campaign (Airborne Methane Mass Balance Emissions in Colorado,
Twin Otter, 28 June – 13 July 2024).

**What the analysis does.** Ethane is co-emitted with fossil (thermogenic) methane
and is essentially absent from biogenic methane, so the airborne ethane-to-methane
enhancement ratio separates the two. Because no AMMBEC flight encircles the metro
area, the emission rate is *not* obtained from a closed-loop mass balance; instead
each flight's CH4:CO and CH4:CO2 enhancement-ratio slope is scaled by an
independent, box-consistent gridded CO or CO2 inventory.

Headline results, all regenerated by this code:

| Quantity | Value | Emitted by |
|---|---|---|
| Fossil fraction of urban methane (per flight) | 2 to 47%, median 29% | `results/table1.csv`, `results/paper_values.json` |
| Urban CH4 emission, CH4:CO x GRA2PES | 4.6 to 10.7 t/h (median 7.6) | `results/emission_estimates.csv` |
| Urban CH4 emission, CH4:CO2 x Vulcan | ~4.1 t/h | `results/emission_estimates.csv` |
| EPA-NEI 7-county upper bound | 11.1 to 25.8 t/h | `results/paper_values.json` |
| Endmember sweep (beta 0.04–0.20) | median crosses 50% only below 0.059 | `results/beta_sensitivity.csv`, `results/beta_breakeven.csv` |
| Production-area endmember *sensitivity* (0.0813) | median 36%, 2 of 7 at or above 50% | `results/beta_endmember_ARC.csv` |

## Quick start

```bash
git clone https://github.com/pdez90/methane_AMMBEC.git
cd methane_AMMBEC

export METHANE_DATA_DIR="$HOME/MethaneData"          # where the inputs live
export METHANE_OUT_DIR="$HOME/MethaneData_outputs"   # where results are written

Rscript setup.R      # reports R version, which optional packages you have, resolved paths
Rscript run_all.R    # runs the pipeline end to end
```

Both environment variables are optional; they default to `~/MethaneData` and
`~/MethaneData_outputs`. Nothing in the code contains a machine-specific path.

`run_all.R` stops on failure of a **required** stage and only warns on optional
ones, so the run never reports success when a core analysis errored. Stages whose
input data or package is missing are skipped with a message rather than failing.

## Dependencies

The aircraft and ground-car stages run on base R (R >= 4.0). The full set of numbers in
the paper also needs `ncdf4` and `terra` with the gridded EPA GHGI file: stage 14
(inventory comparison) writes `inventory_comparison.csv`, which the required stage 21
reads, and stages 13 and 53 need the lidar and GHGI NetCDF files. `setup.R` reports
which packages you are missing:

| Package | Needed for |
|---|---|
| `ncdf4` | lidar boundary-layer height (08, 13), gridded EPA GHGI (14, 32, 33, 53); manual stages 18, 36, 57, 64 |
| `terra` | Vulcan box sum (16), basemaps and overlays (20, 25, 26), EPA cell comparison (58) |
| `png` | combined source figure, Fig 4A/4B (30) |
| `sf`, `tigris` | `make_metro_outline.R` (one-time; its output is committed); `sf` also by the unused 46 |
| `jsonlite` | Carbon Mapper catalogue snapshot (43, manual) |
| Python `python-docx` | the manuscript-edit scripts `scripts/47..98_*.py` (not part of the R pipeline) |

Scripts 16, 17 and 18 are **one-time preparation** steps: they sum the gridded
inventories over the exact analysis box, and the resulting scalars are recorded in
`config.R` (`E_CO_DENVER`, `E_CO2_DENVER`, `E_CO_NEI`, `E_CH4_GRA2PES`). `run_all.R`
re-runs 16 when the Vulcan file is present; 17 and 18 are run by hand, so the main
pipeline runs without the multi-GB inventory archives. `make_metro_outline.R` is likewise one-time; its
output (the seven-county outline) is committed.

## Interactive explorer

`shiny/` holds a Shiny app that reads the pipeline outputs (exported by
`scripts/86_shiny_export.R` into `shiny/data/`) and lets a reader set the ethane endmember,
with the paper's reference values as presets, and browse the flights, ground plumes,
inventories and STILT results. Run it with `Rscript -e 'shiny::runApp("shiny")'` or deploy
it on Posit Connect Cloud from this repository (`shiny/README.md`).

## results/

The small pipeline outputs are committed so that **every number in the manuscript
can be checked without obtaining the raw data**. They must be refreshed and
committed whenever a constant in `config.R` changes, or they will contradict the
manuscript; `results/paper_values.json` records the `source_ratio` actually used,
which is the quickest way to tell whether they are current. They are produced by the code in
this repository, not entered by hand. `results/paper_values.json` is the single
machine-readable digest of the manuscript's headline values;
`results/sessionInfo.txt` records the R environment of the run that produced them.

Large intermediates (notably `mobile_hotspots.csv`, ~47 MB) are excluded; rerun
the pipeline to regenerate them.

## Key methodological choices

- **Estimators.** The ethane fossil fraction uses the instrument-weighted York
  (2004) bivariate fit. The CH4:CO and CH4:CO2 emission slopes use OLS, because
  plume-to-plume scatter far exceeds the instrument precisions York assumes, so
  York over-steepens on low-correlation flights. Script 29 compares OLS, RMA and
  York per flight.
- **Uncertainty.** Whole level legs are resampled with replacement (B = 2000), so
  the intervals reflect between-plume variability rather than 1 Hz autocorrelation.
  These intervals do *not* include inventory-anchor uncertainty.
- **Per-flight reporting.** Neither the fossil fraction nor the emission is pooled
  into a single campaign slope; the day-to-day variation is itself a result.
- **Reliability screen (emission only).** r >= 0.7, >= 2 contributing legs, anchor
  span >= 10 ppb CO or 2 ppm CO2, and a leave-one-leg-out slope range no wider
  than half the slope. It is deliberately not applied to the fossil fraction,
  where weak ethane correlation is the biogenic signal rather than a bad fit.
- **Endmember.** The mixing model divides the observed slope by the endmember
  (`f = beta_observed / beta_source`), so a lower endmember inflates the fossil
  fraction. `SOURCE_C2H6_CH4 = 0.102` is adopted: the lowest of the four published
  Colorado Front Range mole-fraction ratios compiled in Table 2 of Kille et al.
  (2019, GRL) — 10.2% (Gilman 2017), 16.1% (Kille), 17% (Tzompa-Sosa 2017), 18.7%
  (Fried 2015). The lowest is taken deliberately, because it yields a *higher*
  fossil fraction and so works against the biogenic-dominated conclusion rather
  than for it. These are **mole** ratios; weight ratios differ by a factor of
  0.533 and must not be substituted. The endmember describes gas that leaks
  *upstream* of processing, which is why ethane-stripped gas-plant composition and
  other basins' pipeline gas are not comparable values. `SOURCE_C2H6_CH4_ARC = 0.0813`, measured by the NOAA Air Resources Car in
  DJB production areas during this same campaign, is reported as a sensitivity
  case rather than adopted: it is an *ambient* enhancement ratio, not a
  compositional assay of the gas, so it is diluted by co-sampled biogenic methane
  (that campaign's own apportionment puts the DJB at roughly half biogenic) and is
  a lower bound on the source ratio. It also serves a different purpose in its
  source, which uses the ground-to-aircraft contrast rather than an absolute
  composition. A direct assay of undiluted wellhead and distribution gas — which
  neither value is — remains the outstanding calibration. Script 27 evaluates both.
